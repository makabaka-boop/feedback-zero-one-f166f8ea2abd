# 园区能耗按历史归属分摊作业

把园区能耗按"历史归属"精确分摊到各终点，再在严格行/列守恒约束下做
整数微瓦时取整。纯 Python 标准库实现（仅用 `fractions`、`collections`、
`json`、`tempfile` 等），无任何第三方依赖。

## 1. 输入 / 输出

### 输入（UTF-8 JSON，顶层仅含三个键）

```json
{
  "ends": ["X", "Y"],
  "facts": [["f1", "s", 0, 2, 1]],
  "edges": [
    ["e", "s", "X", 0, 2, "1/2"],
    ["f", "s", "Y", 0, 2, "1/2"]
  ]
}
```

- `ends`：互异终点标识数组。标识为非空 ASCII 字母数字串；终点禁止有出边。
- `facts`：`[id, node, a, b, n]`。`[a,b)` 为左闭右开 UTC 整数秒区间，
  `a < b`；`n` 为该区间内均匀产生的非负整数微瓦时。
- `edges`：`[id, from, to, a, b, w]`。`w` 为十进制正整数 `p/q` 串
  （也接受不带分母的正整数）；允许平行边、允许边随时间生灭。
- 各类 id 全局唯一；布尔不是整数（`true`/`false` 整批拒绝）。

### 输出

```json
{
  "fact_ids": ["f1"],
  "ends": ["X", "Y"],
  "A": [["1/2", "1/2"]],
  "B": [[0, 1]]
}
```

- 行（事实）与列（终点）一律按标识的 **ASCII 码点序**排列。
- `A`：精确积分得到的归属量，元素为约分后的 `p/q` 串（零格为 `0/1`）。
- `B`：整数矩阵。每个格取对应 `A` 格的向下或向上整数；每行和等于原 `n`；
  每列和为对应 `A` 列总量的向下或向上整数；在所有可行解中最小化
  逐格绝对误差总和；平局取**按行展开数值字典序最小**者。
- 事实为空时 `A`、`B` 均为 `[]`。

## 2. 运行方式

```bash
# 入口脚本（隔离模式，不读环境变量/当前目录的模块，推荐）
python3 -I run_allocation.py 输入.json 输出.json

# 或模块方式（普通模式，需在仓库根目录执行）
python3 -m energy_alloc 输入.json 输出.json
```

成功时输出文件以"同目录临时文件 + `os.replace`"**原子替换**；
任何校验/处理失败都不会触碰已有输出文件，并向 stderr 打印单个错误 JSON：

```json
{"path": "facts[0]", "message": "从 s 可达的有效子图存在环"}
```

语法错误（含对象内重复键）路径为 `$`；结构问题给出 JSON 路径与零基下标
（如 `edges[2][5]`）；环与出权重和错误报对应事实下标（如 `facts[3]`）。

## 3. 算法

### 3.1 时间分段与精确积分（`graph.py`）

对每条事实，收集其 `[a,b)` 内所有边的起止时刻作为切段点；每个时段内
有效边集恒定。对每个时段：

1. BFS 求从事实起点可达的子图；
2. Kahn 拓扑排序判定该可达子图**无环**（处理不完即有环，报事实下标）；
3. 校验可达子图内每个非终点节点的出权重和恰为 `1`；
4. 在拓扑序上做 DP：起点份额为 1，`frac[v] = Σ frac[u]·w(u,v)`，
   路径权重连乘、同终点多路自然相加。

段内份额按段长占事实总时长的比例加权，各段累加后乘 `n`，
全程用 `fractions.Fraction` 精确运算，得到矩阵 `A` 的一行。
跨时段的并图允许有环（"伪环"），因为每个时段单独判定无环。

### 3.2 约束取整（`rounding.py`，自写双目标网络流）

令 `A_ij = floor(A_ij) + f_ij`、`B_ij = floor(A_ij) + x_ij`，`x_ij∈{0,1}`：

- 行守恒：`Σ_j x_ij = Σ_j f_ij`（行总量是整数，右边恒为整数 `T_i`）；
- 列守恒：`floor(S_j) ≤ Σ_i x_ij ≤ ceil(S_j)`，`S_j = Σ_i f_ij`；
- 目标：`|x-f| = f + x(1-2f)`，选 1 总数固定，故最小化逐格绝对误差
  等价于最小化 `Σ x_ij·(1-f_ij)`。

建模为带下界的运输流：`SRC→行(容量=T_i)`、`行→列(容量 1)`、
`列→SNK(下界 floor(S_j) 强制、上界 ceil(S_j))`。列下界用标准
超源 SS / 超汇 ZZ 的节点平衡变换强制，上界由边容量严格限制，
并补 `SNK→SRC` 回流边使整体成为循环。

字典序平局不靠二次贪心，而是**直接编码成双目标费用**：每条行→列边
带一对费用 `(主费用 1-f_ij, 次费用 q_r)`。次费用取 `big^(C-rank)`
（rank 为行展开序号、C 为待决策格数、big=C+1），指数权重保证任一
靠前格的次费用大于所有更靠后格次费用之和。最短距离按元组字典序比较，
先最小化绝对误差，再在所有最优解中让尽可能靠前的格取 0，一次
最小费用流即得到行展开字典序最小的最优解。主费用是普通有理数、
次费用是整数，各维护一套 Johnson 势函数，用 heapq Dijkstra 增广，
没有大整数放大，可扩展到较大规模。

## 4a. 能耗修订结算：受理、投递与持久账本

冻结 CLI（第 2 节）完全保留；在此之上新增三个独立进程，全部纯标准库。

### 4a.1 受理协议（结算服务 `POST /submit`）

请求体顶层仅允许 `id` / `base` / `data`：

* `id`：沿用原标识规则——非空 ASCII 字母数字串；
* `base`：非负整数，布尔显式拒绝；
* `data`：冻结实现的完整输入对象，按冻结规则校验，错误路径与冻结 CLI
  完全一致（语法/重复键为 `$`，结构问题带零基下标如 `facts[0][2]`）。

状态机（初态 `v=0 p=0 r=null`），所有判定在单条 `BEGIN IMMEDIATE`
事务内完成，并发受理串行等价：

| 情形 | 结果 |
|---|---|
| 同 `id` 同 JSON 结构 | 幂等回放原回执 `{"v": v}`，状态不变 |
| 同 `id` 异内容 | `409`，拒绝不改状态 |
| 新 `id` 且 `base != v` | `409`（路径 `$.base`） |
| 新 `id` 且 `base == v` | `v += 1`，原子保存原结果、回执 `{"v":v}`、待投批次，200 `{"v":v}` |

非法请求一律 `400`，体为 `{"path", "message"}`，拒绝不产生任何状态变更。
`GET /query` 原子返回 `{"v", "p", "r"}`，`r` 为最新受理版的原结果
（初态 `null`）。

### 4a.2 待投批次与投递（投递进程 → 账本 `POST /ledger`）

消息体 `{"v", "d"}`。`d` 按事实标识、终点标识双重对齐，取**新 B 减
旧 B**：缺格作零，仅保留非零 `[事实id, 终点id, 整数差额]`，按两个标识
的 ASCII 序（先事实后终点）排列；空批次保留为 `[]`，版本号不跳过。

例：事实 `f` 直记终点 `X`，`n` 由 1 改 0，则 `d=[["f","X",-1]]`。

投递进程只认领领先水位的下一版 `p+1`（SQLite 在途租约保证多进程不
重复认领）；网络故障退避重试，通信恢复后自动追平。账本规则：

* 同版同批：回原确认（幂等），余额不再变动；
* 同版异批、越号（`v != 账本当前 v + 1`）：`409`，拒绝不改状态；
* 合法批次在单事务内整批累加 `(事实,终点)` 余额并推进版本，
  `synchronous=FULL` 提交即落盘，之后断连/强退安全，重放不重复记账。

结算库仅在账本确认后重算**连续已确认前缀**推进水位 `p`，禁止跳号与
重复记账。重启后从 SQLite 恢复待投批次、租约与水位，续投追平。

### 4a.3 运行方式

```bash
mkdir -p var
python3 -I run_ledger.py     --db var/ledger.db     --port 8081
python3 -I run_settlement.py --db var/settlement.db --port 8080
python3 -I run_delivery.py   --settlement-db var/settlement.db \
    --ledger-url http://127.0.0.1:8081/ledger          # 守护模式
```

崩溃验收钩子：账本进程设置环境变量
`LEDGER_CRASH_AFTER_COMMIT_VERSION=N` 后，版本 N 落盘后、响应前
立即退出（退出码 27），模拟"远端落盘后、本地确认前强退"。

## 5. 验收测试

```bash
python3 -I tests/run_tests.py
```

- `test_rounding_enum.py`：对 1×4、2×2、2×3、3×2、4×1 等小矩阵，
  用 0/1 组合**暴力全枚举**所有满足行/列约束的解，独立求最小绝对误差
  与字典序最小解，与网络流结果逐一比对；更大矩阵做约束可行性校验
  （50×8、100×10、200×12 规模另做性能与守恒压测）。

- `test_settlement.py`：批次差分（对齐/缺格作零/只留非零/ASCII 序/
  空批保留）、信封 400 路径与冻结错误透传、受理幂等与 409、`{v,p,r}`
  查询、账本越号/异批拒绝、多线程并发受理串行等价、双投递进程不重复
  记账，以及"账本落盘后强退 → 双服务重启 → 续投追平且余额只入一次"。
